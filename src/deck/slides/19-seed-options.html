Cost and latency Milliseconds. Pure SQL over an indexed name column, with no index to build or refresh. The query is fast; the index is the cost. Embedding tens of millions of names is a multi-day build and a standing refresh job. A model call per question. Hundreds of milliseconds upward, and cost tracks query volume. Nothing to compute, but it spends a human turn before the traversal starts.
Precision High on spelling and formatting variants, and every match is explainable to a reviewer. Recall improves on aliases that share no characters. Precision drops, because close in embedding space is not the same legal entity. Strongest on genuinely ambiguous names, because it can read the surrounding context. Highest available, because the person asking knows which entity they meant.
Fails when A real alias shares no characters with the registered name, and the miss is silent. It resolves confidently to the wrong entity, and every hop after that is wrong with it. The same question resolves differently across runs, so answers are hard to reproduce or cache. There is nobody to ask. Scheduled jobs and autonomous agents cannot answer the prompt.

What holds at scaleThe embedding step, not the graph, is the bottleneck — so deterministic SQL stays the default and vector similarity is demoted to an optional edge builder at the fuzzy margins. The two on the right are worth reaching for on the ambiguous tail, not on the whole corpus.
