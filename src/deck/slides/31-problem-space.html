31 Problem space

Two independent decisions sit inside every graph retrieval, and they fail in different ways

This is GraphRAG. The name means nothing more than using a graph to serve retrieval, and the options we walked through are several ways to build one — they differ mainly in how they answer the two decisions below.

One picture, two controls. A user asks for “everything connected to Delta Holdings” — three entities match that string, and whatever the walk reaches comes back in full. Move either control and the frontier changes for a completely different reason.

Problem 1 Which node do we start from?
Problem 2 How much comes back, and can the agent read it?
Walk depth — one input to the volume
Get problem 1 wrong and the answer is silently wrong Resolve to the wrong company and every hop after it is confidently, quietly wrong. No amount of tuning the traversal recovers from it, and nothing in the output looks broken.
Get problem 2 wrong and the answer is correct and unusable Walk far enough to catch the shared registered-agent address and everything attached to it returns with it. Every row is a true fact about something. There are simply more of them than the agent can hold, so the context fills with neighborhood it cannot rank and the answer degrades even though the retrieval was right.
