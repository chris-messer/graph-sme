28 Operating rule

Name the need, standardize the edge contract early, and let benchmark queries decide every climb

✓
Name the need, lay out the options, then recommendSort the need into taxonomy, ontology, or knowledge graph first — the layer determines the tool, not the other way round.
✓
Evaluate the managed semantic stack firstGenie Ontology, UC Glossary, Metric Views, and Relationships before any custom build.
✓
Separate metadata questions from row-level onesMeaning over your assets is an ontology question; following one record to a distant one is a knowledge-graph rung.
✓
Choose the hierarchy encoding for the readerClosure or materialized path, with named business sets materialized as data rather than prose.
✓
Land one edge contractGenie, explorers, algorithms, and agents all consume the same Delta table unchanged.
✓
Precompute heavy work, serve lookupsBatch algorithms and hop closures to Delta; nothing global runs at query time.
✓
Treat entity resolution as first-classDeciding two records are the same thing is reliably the hardest part of a real knowledge graph.
✓
Keep Delta as the system of recordPartner engines and virtualization layers sync outward; governance stays in Unity Catalog.
✓
Benchmark before climbingA rung is only exhausted when your own queries fail on it for a concrete, demonstrated reason.
