Four ways to give an agent memory, and only the top rung can retire a fact

Retrieval decides what is found. Only the last rung decides what may be said. Most clients are on rung two today, which is exactly where the two failures we opened with come from.

Extension · not from the source Framework session memory No build · nothing durable
The agent framework’s own scratchpad or rolling summary. Whatever was said earlier in this conversation is in context, and nothing is written down anywhere. A prototype, or a single-session assistant where no claim outlives the conversation. Nothing survives the session, nothing is governed, and supersession is not even expressible — there is no store in which one fact could replace another.
Where most clients are today Plain vector RAG, no graph Already in place
Embed the corpus, retrieve the nearest chunks, answer from them. This is the stack that produced both wrong answers three slides ago. Single-document factual lookup, where the answer sits inside one passage and nothing contradicts it. Measured at 0.13 mean judged against 0.51 for a typed graph on multi-hop ownership questions — a roughly fourfold gap. And a vector index has no way to state that one fact supersedes another: the 2018 and 2019 records are simply two similar passages, so whichever matches the wording better wins.
Fixes connecting the dots Structure-enriched retrieval Medium · 2–4 weeks
Extract a typed graph from the corpus with schema-constrained extraction, then embed retrieval units that carry the verbatim text and its relationship skeleton. One vector lookup, no traversal at query time, no graph database. Enumeration and cross-document composition — the two shapes plain vector search reliably misses. It maximizes what is found and says nothing about what may be said. A retired fact that is well connected is retrieved just as happily as a current one.
Fixes what may be asserted Governed graph memory Medium–high · 4+ weeks
A typed graph and compiler layer decides what the agent may treat as true, running the four checks from slide 17 at retrieval time. Supersedes edges mean memory updates rather than only appends — the agent can change its mind. The agent’s assertions carry consequences, and someone has to be able to audit why it said what it said. The longest build in this section, and the evidence is one composed benchmark rather than a track record. Standing it up before rung three answers the wrong question first.

Reading this slideRungs three and four are layers rather than alternatives — the source pairs them deliberately and has benchmarked them as one stack. So the sequence is rung three to fix what is found, then rung four when what the agent is permitted to say starts to matter. The dashed rung is ours, included because it is where a surprising number of agents actually are.
