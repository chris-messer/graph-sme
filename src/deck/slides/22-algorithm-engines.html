Three engines run those same four families, and the edge count picks which one

None of these is a graph database, and all three read the same governed edge table and write results back to Delta. The only question is where the computation lands.

Where each engine runs, by edge count
NetworkXserverless notebook
Load edges into NetworkX, run PageRank, Louvain or betweenness, write results back to Delta. No cluster libraries, no GPU, no ceremony.
FitsUp to the low millions of edges, when the client wants an answer this week rather than a platform.
FailsPast a few million edges it exhausts one machine, and there is no distributed path to grow into.
TradeoffThe least setup of the three, and the least headroom. Outgrowing it means rewriting.
Low · days
SparkGraphserverless Spark
A GraphFrames-style API built for serverless that tiers its own execution — pure-Python driver path when the graph fits in driver memory, coarsen-then-solve for mid-size, fully distributed beyond that. pip install, point it at nodes and edges.
FitsThe final graph size is not settled, or one codebase has to hold up at both ends of the range.
FailsA hard latency target on a very large batch job. The distributed tier buys scale, not speed.
TradeoffOne more package to standardize on, against never rewriting when the graph outgrows its tier.
Low–Medium · 1–2 weeks
NVIDIA cuGraphGPU cluster
RAPIDS cuGraph on a GPU cluster. Load edges from Delta, run, write results back to Delta for Genie and agents to read. Field-proven on a utility power network — shortest path and Louvain.
FitsVery large graphs, or batch analytics with a latency target — Louvain over tens of millions of edges.
FailsThe graph is small, or nobody wants to operate a GPU cluster for a job that runs weekly.
TradeoffOrder-of-magnitude speedups over CPU, paid in GPU time and a second runtime to maintain.
Medium · 1–2 weeks

Reading this slideNo column wins outright — the bands overlap on purpose. But one property is worth naming: because SparkGraph’s driver path is pure Python, the same package runs inside a model serving endpoint, where Spark does not exist. That is what lets an agent compute PageRank mid-conversation rather than read a number precomputed last night. At every tier the durable pattern is unchanged: precompute the heavy work to Delta, then serve cheap lookups.
